### 4.1 What a next agent should know before continuing

1. **The tail probe had to be rebuilt.** dataUpdate's own train/val split is per-image over renders sharing a
   source, so 99.2 % of its val side reused a train source. Use `data/dataupdate/index_probe_dj.csv` +
   `glyphs_probe_dj.npz` (group-disjoint: 5 whole font families, 171 whole writer ids), never `index_probe.csv`.
   `scripts/eval_probe.py` reports the hw and ft halves separately — quote the **hw** number.
2. **The probe is a domain proxy, not a score.** It ranks models that share a fine-tuning recipe; it cannot be
   read as expected hidden-test accuracy, and G5 cannot be compared on it at all (it trained on that domain).
3. **Stratified val is finished as a selection tool** — every candidate sits at 0.9897–0.9902, a spread of ~2 images.
4. **ฃ and ฑ have 1 real training image and 0 validation images each.** No amount of model work makes them
   measurable on real data. If the hidden test is class-balanced this is the largest single risk.
5. Two bugs were fixed in place: `prep_dataupdate.py` (`KeyError: 'family'`) and `merge_extra_sources.py`
   (silently dropped 8,118 rows whose images lived in a non-sibling cache — now warns).
6. **Selective tail-fill was tried and is documented in §L of `reports/02-EXPERIMENTS.md`.** The new
   `extra_fill_max_real` config key fills only classes below a real-image threshold. G6 (n_train≤20 → 200)
   posts the best stratified numbers in the project, but over 3 seeds neither G6 nor G7 beats G4 on anything
   measurable (doc balanced p=0.23) while costing macro-F1 (p=0.085). **G4 stays shipped.** If the teacher
   confirms the hidden test is class-balanced, switch to `configs/gen/G6_r18_g2init_randaug_fill200_max20.yaml`.
7. **The measurement, not the model, is now the bottleneck.** 8 of the 24 starved classes have zero
   document-disjoint validation images and the rest have 2–20, so one image flipping moves 72-class balanced
   accuracy by 0.46 pt. Labelling ~20–30 real images per class for the 14 scarcest classes (~400 images) would
   buy more than any further synthetic generation, because it restores the ability to *measure*.
8. **Never run `uv` under `/mnt/d/...` from WSL.** Doing so deleted and recreated the Windows copy's `.venv`
   as a Linux one (`--no-sync` stops a re-sync, not venv re-creation). Work in `~/work/thaichar72`.
9. Notebook: `notebooks/ThaiChar72_Colab.ipynb` is now 20 cells with a **§5B Error Explorer** (per-sample

   monitoring, `show_class()`), runs clean in JupyterLab and headlessly via `scripts/run_notebook_local.py`.

### 4.2 Added 2026-09-22 evening / 09-23 — stress suite, a deployment bug, and the day kit

10. **`scripts/stress_suite.py` (TASK-14)** measures all five packaged weights on input we never trained
    for: degraded (A), invalid (B — no correct answer exists, so no accuracy is reported anywhere), and
    identity-changing (C — a mapping, not a score). 28 s for the whole run. Results in `reports/stress/`,
    written up as `reports/02-EXPERIMENTS.md` §N. `notebooks/ThaiChar72_StressEval.ipynb` is for checking
    those conclusions: every table has a drill-down showing the images and what the model said.
11. **Its acceptance check caught a real deployment bug** (§N.0). `infer.preprocess_image` scored 0.9695
    where the training-time dataset transform scored 0.9898 on the same 492 images — wrong on 10, right on
    none. `_reframe` padded tight crops with the *median* of the four corners, which is ink-coloured when
    strokes touch them; Otsu then read the pad as background and inverted the image. It also silently
    defeated `--polarity both`, because inverting the input moved the bad guess instead of fixing it. Fixed
    by taking the **lightest** corner. **Every inference-path number produced before that fix was ~2 pt low.**
12. **Rotation was the one big fixable gap** (retention 0.52 at 30°, 0.10 at 45°; `robustness.py` never
    tested past 20°). `predict_with_rotation_search` re-reads only images the model is unsure about
    (`tau=0.85`, 3 % of clean input) and accepts a rotated reading only if it beats upright by
    `margin=0.30`. **+37.7 pt at 30°, +75.1 pt at 45°, 0.00 pt on clean.** End to end on real files: a
    folder rotated 35° goes 0.2429 → 0.8286. Enable with `--rotation-tta`. §N.6.
13. **Widening augmentation to match the other measured fragilities did NOT work.** A 5×5 stroke kernel made
    erosion robustness *worse* (0.25 → 0.16 — it destroys thin glyphs and the ink guard then discards them)
    and a wider downscale range moved pixelate by −1.2 pt. `aug: randaug_hard` now widens rotation only
    (G9 → `weights/thaichar72_r18_64_gen_rotaug.pt`). Isolate one variable at a time. §N.6.
14. **The pixelate "cliff" is not a real risk** (§N.7). The model scores **0.974 on real glyphs under 9 px**
    and the corpus already contains them (8.5 % below 12 px). The 0.68 figure comes from *downscaling* a
    20 px glyph, which destroys stroke detail a natively small glyph never had — down-only is the worst of
    the three resampling variants, so it is not an upscaling artefact. A low-resolution scan is the 0.97
    case. Do not spend time here.
15. **`scripts/triage_input.py` is the first thing to run on the day.** Label-free: it reports resolution,
    ink weight, polarity and rotation against the corpus and prints the `evaluate_folder.py` command to use.
    Its rotation test needs **agreement on the winning angle**, not a confidence lift — lift alone also
    fires on blurred and low-resolution batches that are not rotated (it called 3 of 5 probe folders
    rotated when only 1 was).
16. **Never flip, and check orientation before trusting a batch** (§N.3). 127 class × transform pairs become
    a *different real Thai character* confidently; บ↔ภ and ย↔ถ are exact reciprocals under vertical
    mirroring. This is the measurement behind `CLAUDE.md`'s ban on flip augmentation.

## 5. Hand-in day (hackathon format) — read this before the day

Unseen data, one hour, repeated runs allowed, best result counts. Two things decide that hour.

### 5.1 One command scores everything

```bash
uv run --no-sync python scripts/evaluate_folder.py --dir /path/to/test_data
```

Recursive discovery; labels read from folder names (`161`, `161ก`, or the bare Thai character) or
`--labels-csv`; `--no-labels` for prediction-only. Scores **all five packaged weights and ranks them**
(493 images × 5 models ≈ 4 s), reports class coverage and balance, names files it could not label, and
warns if the whole set comes out inverted. Per-model prediction CSVs land in `outputs/onsite/`.

### 5.2 Input framing was a silent 47-point cliff — fixed, but know the trade

`preprocess_image` used to read polarity off the 1-px border ring. On 493 held-out glyphs:

| input framing | before | after |
|---|---:|---:|
| correctly framed | 0.9939 | 0.9696 |
| tight crop | 0.9229 | 0.9696 |
| **zero-padded (dark frame)** | **0.4949** | **0.9696** |
| upscaled 4× | 0.9148 | 0.9513 |

`_reframe()` peels constant border rings and re-pads with the background the corners reveal, so every
framing now lands in the same place. **It costs 2.4 pt on perfectly framed input** — deliberate, because
the format is unknown and round2's own crops are tight. If the test data turns out to be well framed,
that 2.4 pt is recoverable by reverting `_reframe` (commit 68197da).

### 5.3 Take all five weights; do not guess the label convention

| weight | trained on | covers the case where |
|---|---|---|
| `thaichar72_r18_64_gen.pt` | G4, label v2 | default |
| `thaichar72_r18_64_gen_v3labels.pt` | same recipe, label v3 | the key is cleaner than ours |
| `thaichar72_resnet18_64.pt` | K1 | — |
| `thaichar72_resnet18_64_v1labels.pt` | pre-DataV2 labels | the key follows the original convention |
| `thaichar72_mnv3small_64_small.pt` | 1.6 M params | speed matters |

### 5.4 Known weaknesses to expect on unseen data

- **ฃ and ฑ**: one real training image each, no validation images at all. Unknown, not perfect.
- **Class ่ (mai ek)** is a 3×7 to 8×10 pixel blob in this corpus, so the model identifies it by size
  rather than shape. Higher-resolution ่ in the test data is a plausible failure.
- Half the class list (35 classes, 3.4 % of the corpus) is thinly trained; the tail probe puts the
  baseline at 22.6 % on unseen writers for those classes, G4 at 42.9 % (§K).
- Label cleaning is done and made **no measurable difference** (§M) — do not spend the hour on it.
