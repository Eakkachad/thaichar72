### สไลด์ 5 — สถาปัตยกรรม CNN `1:00`

**ต้องอธิบาย 2 อย่าง: โครงสร้างภาพรวม + จุดเด่นของสถาปัตยกรรม** ← เช็กลิสต์ข้อ 4 และ 8

```
ภาพ 64×64×3
  → ResNet-18 (11.2M params)
      conv 7×7 → maxpool → 4 stage residual block → global avg pool → 512 มิติ
  → + ฟีเจอร์เรขาคณิต 4 ค่า (สูง กว้าง สัดส่วน ความหนาแน่นหมึก)
  → Linear → 72 คลาส
```

**จุดเด่นที่ต้องพูดให้ได้ — Residual / Skip Connection**

> "ResNet มีทางลัดที่บวกค่า input กลับเข้าไปที่ output ของแต่ละบล็อก `x + F(x)`
> ทำให้ gradient ไหลย้อนกลับได้โดยไม่จางหาย เทรนโครงข่ายลึกได้จริง
> เรื่องนี้จำเป็นกับงานนี้เพราะตัวอักษรไทยหลายคู่ต่างกันแค่รายละเอียดเล็กๆ เช่นหัวกลมหรือหาง
> ต้องใช้ชั้นลึกๆ จับลักษณะระดับสูง"

**เหตุผลที่เลือก (ใส่ตารางสั้นๆ)**

| backbone | params | Accuracy | เวลา/ภาพ |
|---|---:|---:|---:|
| **ResNet-18** | 11.2 M | **99.02 %** | 5.6 ms |
| EfficientNet-B0 | 4.1 M | 99.01 % | 6.4 ms |
| ConvNeXt-Tiny | 27.9 M | 98.98 % | ช้ากว่า |
| MobileNetV3-Small | 1.6 M | 99.00 % | 3.4 ms |

> พูดปิด: "เราทดลอง 4 สถาปัตยกรรม ได้ใกล้เคียงกันหมด **แปลว่าที่ขนาด 64 พิกเซล
> สูตรการเทรนสำคัญกว่าตัวสถาปัตยกรรม**" ← ประโยคนี้แสดงว่าเข้าใจจริง

### สไลด์ 6 — Transfer Learning `1:10` ⭐ 1.5 %

**จุดขายหลัก: เราใช้ 2 ชั้น ไม่ใช่ชั้นเดียว**

```
ImageNet 1.2 ล้านภาพธรรมชาติ
   │  ชั้นที่ 1 — ถ่ายโอนลักษณะทั่วไป: ขอบ มุม เส้นโค้ง
   ▼
ตัวอักษรไทยสังเคราะห์ 126,114 ภาพ จาก 203 ฟอนต์
   │  ชั้นที่ 2 — ถ่ายโอนความรู้เฉพาะทาง: "ตัวอักษรไทยหน้าตาแบบไหน"
   ▼
ข้อมูลจริง 47,949 ภาพ  →  โมเดลสุดท้าย
```

**หลักฐานที่ทรงพลังที่สุด — ใส่ให้ได้**

| stage-1 เทรนด้วยข้อมูลสังเคราะห์ล้วน | Accuracy บนภาพจริง |
|---|---:|
| ไม่เคยเห็นภาพจริงเลยสักภาพ | **93.96 %** |

> พูด: "โมเดลชั้นที่สองนี้เทรนด้วยตัวอักษรที่เราสังเคราะห์เองล้วนๆ **ไม่เคยเห็นภาพจริงเลยสักภาพ**
> แต่พอเอาไปวัดกับภาพจริงได้ 94 % นี่คือหลักฐานว่าความรู้ถ่ายโอนได้จริง"

**ผลลัพธ์ของการ pretrain ที่ดีกว่า**

| stage-1 | ฟอนต์ที่ไม่เคยเห็น 62 แบบ |
|---|---:|
| 26 ฟอนต์ (สูตรเดิม) | 83.4 % |
| **203 ฟอนต์ + ข้อมูลเสริม** | **86.8 %** |

### สไลด์ 7 — Data Augmentation `1:00` ⭐ 1.5 %

**เราทำ 2 ระดับ**

**ระดับที่ 1 — สังเคราะห์ตัวอักษรใหม่ทั้งภาพจาก 203 ฟอนต์**

| ขั้น | ทำอะไร |
|---|---|
| 1 | render จากฟอนต์ความละเอียดสูง |
| 2 | สุ่มขนาดจาก**การกระจายจริงของคลาสนั้น** |
| 3 | ปรับความหนาเส้นให้ตรงกับของจริง |
| 4 | ย่อ + ใส่ noise + JPEG artifact |

รูป: [`reports/figures/synth_vs_real.png`](../reports/figures/synth_vs_real.png) — **เทียบของสังเคราะห์กับของจริงข้างกัน**

**ระดับที่ 2 — RandAugment ระหว่างเทรน** สุ่ม 2 op จาก 9 op:
affine, margin, stroke, resolution, elastic, speckle, blur, erasing, rebinarize
รูป: [`reports/figures/aug_examples.png`](../reports/figures/aug_examples.png)

**ผลเปรียบเทียบ — เงื่อนไขเดียวกันทุกอย่าง ต่างแค่ augmentation**

| สูตร | Accuracy | **ความทนทาน** |
|---|---:|---:|
| ไม่ใช้เลย | 98.04 % | – |
| morph (ไม่มี noise) | 98.20 % | 0.850 |
| trivial | 98.55 % | 0.893 |
| **RandAugment** | 98.39 % | **0.905** |

> **ประโยคสำคัญที่ควรพูด:** "บน validation ธรรมดา augmentation แทบไม่ต่างกันเลย ไม่ถึงครึ่งจุด
> แต่พอวัด**ความทนทานต่อภาพเสีย** ต่างกันถึง 5.6 จุด
> ถ้าเราดูแต่ accuracy เราจะเลือกผิด" ← ประโยคนี้ตอบคำถาม "ทำไมต้องทำ augmentation" ได้ตรงที่สุด

เมื่อรวมกับ Transfer Learning ที่ดีกว่า (สไลด์ 6) ได้ **99.02 % / ความทนทาน 0.915**

> 🚫 **ประเด็นที่ต้องพูด:** "เราห้าม flip ทุกกรณี เพราะตัวอักษรไทยไม่สมมาตร
> และเรา**วัดแล้ว** — พลิกแนวตั้งทำให้ บ กลายเป็น ภ และ ย กลายเป็น ถ สลับกันพอดี"

### สไลด์ 9 — แนวคิดที่น่าสนใจ `1:20` ⭐⭐ 2 % — **สไลด์ที่สำคัญที่สุด**

เลือก **2 เรื่อง** อย่าใส่หมด จะไม่ทันเวลา

#### เรื่องที่ 1 — "ตัวอักษรไทยพลิกแล้วกลายเป็นตัวอื่น" (วัดได้ 127 คู่)

| การแปลง | กลายเป็น |
|---|---|
| กระจกแนวตั้ง | **บ ↔ ภ**, **ย ↔ ถ** (สลับกันพอดีทั้งสองทาง) |
| กระจกแนวนอน | า → ก, แ → ม |
| กลับหัว | ว → ย, ิ → ั |

> "ตำราบอกว่าห้าม flip ตัวอักษร แต่ไม่มีใครบอกว่าเกิดอะไรขึ้นถ้าทำ เราวัดจริงทั้ง 72 คลาส
> พบ 127 กรณีที่**กลายเป็นตัวอักษรไทยอีกตัวหนึ่งแบบที่โมเดลมั่นใจมาก** คือผิดแบบเงียบๆ
> ซึ่งอันตรายกว่าผิดแบบไม่มั่นใจ"

**ใส่ภาพ:** คู่ต้นฉบับ/หลังพลิก จาก `show_flip("mirror_v")` ใน StressEval notebook

#### เรื่องที่ 2 — Rotation search: แก้จุดอ่อนโดยไม่ต้องเทรนใหม่

> "เราพบว่าถ้ากระดาษเอียง 30 องศา ความถูกต้องตกจาก 99 % เหลือ 52 %
> แนวคิดของเราคือ **โมเดลเทรนบนตัวอักษรตั้งตรง ดังนั้นมุมที่โมเดลมั่นใจที่สุด = มุมที่ตั้งตรง**
> จึงหมุนภาพไปทีละมุมแล้วเลือกคำตอบที่มั่นใจสุด"

| | ตั้งตรง | หมุน 30° | หมุน 45° |
|---|---:|---:|---:|
| ไม่ใช้ | 98.58 % | 51.93 % | 9.74 % |

## 3. เตรียมตอบคำถาม (5 นาที)

| คำถามที่น่าจะโดน | คำตอบสั้น | หลักฐาน |
|---|---|---|
| ทำไมเลือก ResNet-18 | ทดลอง 4 backbone ได้ใกล้เคียงกัน เลือกตัวที่เร็วและเสถียร | §5.2 METHODOLOGY |
| 99 % สูงเกินจริงไหม | เป็นไปได้ จึงวัดบน doc-disjoint ด้วย ได้ 98.72 % | §3.3 |
| คลาสที่มีภาพเดียวทำยังไง | สังเคราะห์เพิ่มตอน pretrain แต่**ยอมรับว่ายังวัดผลไม่ได้** เพราะไม่มีภาพ validation | §14 |
| Data Augmentation ใช้อะไรบ้าง | RandAugment 9 op + สังเคราะห์จาก 203 ฟอนต์ **ห้าม flip** | §7 |
| Transfer Learning จากอะไร | ImageNet → ตัวอักษรสังเคราะห์ → ข้อมูลจริง (2 ชั้น) | §6 |
| ถ้าข้อมูลทดสอบหน้าตาไม่เหมือนที่เทรน | ทดสอบไว้แล้ว 3 กลุ่ม 40+ สภาพ มีเครื่องมือ triage | §11 |
| Overfit ไหม | 3 seeds ได้ 98.99 ± 0.04 % และ doc-disjoint ต่างกันแค่ 0.3 จุด | §9.3 |
| ทำไมไม่ใช้ ensemble | **ลองแล้วไม่ช่วย** — majority vote แพ้โมเดลเดี่ยว | วัดไว้แล้ว |

**เคล็ดลับตอบคำถาม:** ถ้าไม่รู้ ให้ตอบว่า *"เรื่องนี้เรายังไม่ได้วัด"* — ดีกว่าเดา
เรามีข้อมูลรองรับเยอะมาก ใช้จุดแข็งนี้
