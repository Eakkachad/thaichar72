# Data audit — `DataV2` and `dataUpdate` drops (2026-09-22)

Two archives arrived from teammates. The owner's brief described them as "a clean dataset" and "another
dataset that looks like the first one in parts, but maybe not as clean". **That description turns out to be
wrong in a way that matters:** they are not two labellings of the same corpus. One is a corpus, already
consumed; the other is a *synthetic data generator plus its output*, and it is the only one carrying new
information.

All numbers below were produced by direct file-level comparison against `reports/eda/files.csv` (the tracked
manifest of the original corpus, 62,707 rows with per-file md5).

---

## 1. `DataV2-20260922T071230Z-1-001.zip` — already fully consumed

Contents: `datav2.zip` (the images), a `CHANGELOG.md`, 7 EDA figures, and four CSVs
(`split_manifest_v2.csv`, `split_stats_v2.csv`, `num_class_mapping.csv`, `swap_verdict.csv`).

| Check | Result |
|---|---|
| Classes | 72 — exactly the project's class universe, no extras |
| Images | 64,354 = 62,532 real + **1,822 `aug_` files** |
| Real images also present in `files.csv` | **62,520 / 62,520 — every single one** |
| Real images *not* in the original manifest | **0 (zero new images)** |
| Label moves proposed vs. original manifest | 643 |
| …of which already accepted in `reports/analysis/datav2_label_changes.csv` | **629** |
| …still outstanding | **14** |
| Files DataV2 drops | 185 → 175 already dropped by our audit, 10 extra |

**Conclusion.** This is the same DataV2 the project audited on 2026-09-19. Its value was already extracted
into `data/splits/split_seed42_v2.csv`. The 14 outstanding moves are all inside the
า / ว / จ / ใ confusion cluster and are listed in §4.

**The 1,822 `aug_` images must not be used.** They are rotate/translate/scale/shear/noise/brightness
variants of images that are already in the corpus, produced *before* the train/val split. Admitting them
would (a) add no information and (b) put augmented copies of a training image into validation, inflating
every number we report. Our own augmentation is applied after the split, on the fly, which is the correct
order. `scripts/restore_round2_from_datav2.py` skips every `aug_` file by construction.

### 1.1 It did give us one thing back: the corpus itself

The original `ThaiCharacter Dataset/` was not carried over to this machine. Because DataV2 turns out to
contain byte-identical pixel data, the original tree was reconstructed by placing every file back under the
class code recorded in `files.csv`:

```
restored     : 62,522
md5 verified : 62,522
md5 mismatch : 0
missing      : 185   (175 already dropped by our audit + 10 in า/๐)
```

Zero md5 mismatches across 62,522 files is conclusive: the restored tree is the original corpus, so the 93
historical runs, the splits and the caches all stay comparable. See `reports/analysis/round2_restore.json`.

## 2. `dataUpdate-20260922T071153Z-1-001.zip` — the real new asset

Not a relabelling of round2. It is a **synthetic Thai character generator plus 98,071 rendered images**:

- `build_thaichar_dataset.py` + `thaichar_core.py` — the generator, re-runnable with different settings
- `fonts/` — **167 Thai font files, 31 families**, Google Fonts (OFL / Apache-2.0)
- `tools/round2_cache.json` — per-class size and ink-fraction statistics scanned from round2
- `dataset/` — 98,071 images, 50 classes, with a `manifest.csv` recording source (`hw`/`ft`) and font name

The author domain-matched the output to round2 rather than rendering clean glyphs: binary 0/255 pixels, the
real per-class height distribution, per-class ink-fraction quantiles reached by dilate/erode at high
resolution before downscaling, 55/45 polarity, JPEG quality 72–96. Sources are 73,428 font renders and
24,643 real pen-written glyphs (from handwriting datasets) pushed through the same degradation pipeline.

### 2.1 Only 35 of its 50 classes are usable

| | classes | images |
|---|---:|---:|
| In our 72-class universe | **35** | **68,071** |
| Outside it | 15 | 30,000 |

The 15 unusable classes are ฅ ฆ ฌ ฎ ฦ ะ ำ ฺ ฿ ๋ ํ ๎ ๏ ๚ ๛ — the generator's author worked from a different
72-class definition than the assignment's. They cannot appear in a 72-way classifier, but they are still
useful as *extra pretraining classes* (§5, E3).

## 3. Why this is the highest-value thing available: the tail is unmeasured

The 35 classes `dataUpdate` covers are precisely the starved ones. Real images per class in round2, and the
size of their validation sets:

| | |
|---|---|
| Real images across those 35 classes | ~2,100 = **3.4 % of the corpus** |
| Share of the class list | **35 / 72 = 49 %** |
| Validation images per class | **1 – 31** |
| Classes with `n_val = 0` | ฃ (n_train = 1), ฑ (n_train = 1) |
| Classes with `n_val ≤ 3` | ฬ, ๗, ฮ, ๖, ฤ, ๔, ๕, ๙, ึ |

The headline 99.03 % top-1 of the shipped model is therefore dominated by the head of the distribution, and
roughly half the class list is effectively untested. `reports/analysis/K1_r18_kd_20/worst_classes.md` shows
the symptom directly: ๘ sits at 60 % recall on a validation set of **five images**, and two classes have no
validation images at all.

Two distinct risks follow, and they need different fixes:

1. **If the hidden test is anywhere near class-balanced**, half the classes are near-untrained and this is
   where the marks are. `dataUpdate` is the only asset that addresses it.
2. **If the hidden test is long-tailed like round2**, the tail barely moves the score, and the remaining
   headroom is in the head-class confusions — which are substantially *label noise*, not model error:
   K1's two largest error modes are า↔ๅ (30 + 16 errors) and ั↔้ (13 + 4), and `swap_verdict.csv`
   independently reports both clusters as still contaminated.

The plan in §5 covers both, because we cannot see the test set.

## 5. What this changes about the plan

The goal is a model that **generalises**, not one that scores well on our own validation split. The audit
points the work at three things:

- **E1 — font-diversity pretraining.** The real prize in `dataUpdate` is the 167 fonts plus a re-runnable
  generator, not its images. Merged with the repo's 26 fonts and the Windows Thai print faces
  (THSarabun, Angsana, Browallia, Cordia, the UPC family, Leelawadee — the typefaces scanned Thai documents
  are actually set in), the pool is **203 typefaces vs 26**. Stage-1 pretrains on all 72 classes rendered
  across that pool with wide degradation; stage-2 fine-tunes on real data. This is the pattern the project
  already established as the winner (B6a: synthetic as *pretraining* beat synthetic as extra data).
- **E3 — 87-way pretraining.** Keep `dataUpdate`'s 15 out-of-universe classes as extra stage-1 classes, then
  fine-tune a 72-way head. Harder negatives at zero inference cost.
- **E6 — targeted label-noise cleanup** on the pairs `swap_verdict.csv` flags and the confusions K1 actually
  makes, with the v1-label model retained as a hedge in case the hidden test follows the original convention.

Selection stays on the **document-disjoint split plus the robustness gate**, not the stratified validation
split, because those are the criteria that track generalisation.
